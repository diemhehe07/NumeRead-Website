# Firestore access review — personalized learning paths

## Scope reviewed

- Web app: plain HTML/CSS/JavaScript using the Firebase Firestore compat SDK.
- Firestore collections used by the client: `students`, `sectionCounters`,
  `learningMaterials`, `teacherAccounts`, `pretestResults`, `activityLogs`,
  and `teacherActions`.
- Queries used by the teacher dashboard: students filtered by the verified
  teacher's section and learning materials ordered by creation date. Student
  sign-in performs a single-document read scoped to its section/student ID.

## Personalized assignment design

The implementation stores the teacher-selected path in the existing
`students.assignedPath` string, which is already schema-validated and readable
by the learner who owns that student document and the teacher for that section.
It contains only the recommended focus, built-in module title, and activity
titles; no new personal data, permissions, or collection access is added.

## Rule review and attack checks

- Unauthenticated reads and writes remain denied.
- Cross-section teacher updates remain denied: the student update requires the
  existing section to match the verified teacher profile.
- Student ownership/section takeover remains denied by immutable-field checks.
- Schema pollution is prevented because no new student field is introduced.
- No new permission, collection access, or role escalation is introduced.

No Firestore rules change is required for this feature because it uses the
existing, validated `assignedPath` field. This is a focused review rather than
an exhaustive production security audit.
